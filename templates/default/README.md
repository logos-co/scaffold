# Program Deployment Scaffold

This project was generated by `logos-scaffold` for the
[Logos Execution Zone](https://github.com/logos-blockchain/logos-execution-zone)
(LEZ) **0.3** standalone sequencer. The programs under `methods/guest/src/bin`
and the runners under `src/bin` are LEZ's own `examples/program_deployment`,
copied from the pinned release.

## Prerequisites

- `git`, `rustc`, `cargo`
- Docker and `cargo-risczero` for the default reproducible guest build, or set
  `[build].guest = "local"` in `scaffold.toml` (or pass `--guest local`) to use
  the host risc0 toolchain (`rzup install rust`)
- Nothing else: `logos-scaffold setup` builds the pinned `sequencer_service`
  and `wallet`, and the LEZ build downloads its own circuits release

## First run

```bash
logos-scaffold run
logos-scaffold wallet -- check-health
```

`run` builds the workspace and guest programs, starts the localnet, tops up the
project's default wallet, and deploys every program. The first run also
performs `setup`, which:

- initializes the project wallet under `.scaffold/wallet` (export
  `LOGOS_SCAFFOLD_WALLET_PASSWORD` first if you do not want the default
  development password) and records its first public account as the default in
  `.scaffold/state/wallet.state`;
- imports the localnet's **dev funder** account. LEZ 0.3 has no faucet: the
  localnet funds this well-known development key at genesis, and
  `logos-scaffold wallet topup` transfers from it.

### Step by step

```bash
logos-scaffold setup
logos-scaffold localnet start
logos-scaffold build
logos-scaffold wallet topup        # fund the default account (it pays fees)
logos-scaffold deploy
```

LEZ 0.3 charges fees on public transactions, so the default account must be
funded before it can deploy or call anything.

## How deployment works in LEZ 0.3

A program is uploaded through the `program_loader` builtin: its code is split
into segment accounts, and a header account points at them. **The header
account id is the program id** that transactions name. `logos-scaffold deploy`
creates fresh wallet accounts for the header and segments, pays the fees from
the default account, and records each program id in
`.scaffold/state/deployments.json`:

```bash
logos-scaffold deploy hello_world --json
cat .scaffold/state/deployments.json
```

Every deploy creates a new header, so re-deploying gives a new program id.

## Run the examples

The runners are LEZ's own: each one deploys a fresh copy of its program (paid
by the account you pass), then sends a transaction to it. They take the guest
binary path, plain base58 account ids (no `Public/` prefix), and a funded
payer.

```bash
# Where `build` put the guest binaries:
#   default (docker) build: target/riscv-guest-docker/riscv32im-risc0-zkvm-elf/docker
#   --guest local build:    target/riscv-guest/example_program_deployment_methods/example_program_deployment_programs/riscv32im-risc0-zkvm-elf/release
export BIN_DIR=$(pwd)/target/riscv-guest-docker/riscv32im-risc0-zkvm-elf/docker

# The funded default account pays (strip the `Public/` prefix):
export PAYER=$(sed -n 's/^default_address=Public\///p' .scaffold/state/wallet.state)

# A fresh account for the program to write into:
logos-scaffold wallet -- account new public
#   Generated new account with account_id Public/<id> at path /<n>
export ACCOUNT=<id>

export LEE_WALLET_HOME_DIR=$(pwd)/.scaffold/wallet
cargo run --bin run_hello_world -- "$BIN_DIR/hello_world.bin" "$ACCOUNT" "$PAYER"
logos-scaffold wallet -- account get --account-id "Public/$ACCOUNT"
```

The runners read the wallet from `LEE_WALLET_HOME_DIR` and its password from
stdin, exactly like `logos-scaffold wallet -- ...`. The other runners follow
the same pattern:

```bash
cargo run --bin run_hello_world_with_authorization -- "$BIN_DIR/hello_world_with_authorization.bin" "$ACCOUNT" "$PAYER"
cargo run --bin run_hello_world_through_tail_call -- "$BIN_DIR/simple_tail_call.bin" "$BIN_DIR/hello_world.bin" "$ACCOUNT" "$PAYER"
cargo run --bin run_hello_world_with_move_function -- "$BIN_DIR/hello_world_with_move_function.bin" "$PAYER" write-public "$ACCOUNT" Hola
cargo run --bin run_hello_world_with_authorization_through_tail_call_with_pda -- "$BIN_DIR/tail_call_with_pda.bin" "$BIN_DIR/hello_world_with_authorization.bin" "$PAYER"
```

The `_private` runners execute privately and generate a zero-knowledge proof
on your machine; with `RISC0_DEV_MODE=1` (see `.env.local`) the proof is
skipped. They need a private account (`logos-scaffold wallet -- account new
private`).

## Useful commands

```bash
logos-scaffold localnet status
logos-scaffold localnet logs --tail 200
logos-scaffold doctor
logos-scaffold wallet list
logos-scaffold wallet -- --help
```

The localnet keeps its chain in `.scaffold/localnet`; `logos-scaffold localnet
reset --yes` wipes it (and the recorded program ids).
